1. 사용한 데이터

AI4I 2020 Predictive Maintenance Dataset (UCI Machine Learning Repository, id=601) · 10,000행 × 14열. 실제 설비에서 수집한 기록이 아니라 밀링 머신의 거동을 모사해 생성한 공개 합성 데이터입니다. 설비 명칭만 P&T 다이싱 공정으로 각색했으며, 밀링과 다이싱은 모두 고속 회전 공구로 재료를 절삭하는 동종 설비입니다. 센서 5종(공기온도·공정온도·회전속도·토크·공구마모)과 고장 유형 5종이 라벨로 들어 있습니다.

값의 범위는 원본 그대로입니다. 회전수 1,168~2,886rpm은 밀링 머신의 범위이며, 실제 다이싱 스핀들은 이보다 한 자릿수 이상 높게 돕니다. 임계 판정 논리를 보이는 것이 목적이라 값을 실제 범위로 옮기지 않았습니다. 옮기면 데이터셋 문서에 검증된 임계 조건을 그대로 쓸 수 없게 되고, 그때부터는 전부 제가 지어낸 숫자가 됩니다.

L·M·H는 설비 등급이 아니라 그 설비가 가공하는 제품의 품질 등급입니다(원본의 Type). 등급이 높을수록 공구 마모가 빠르고(제품 1개당 L 2min / M 3min / H 5min), 과부하 임계도 달라집니다(11,000 / 12,000 / 13,000 minNm). 검증셋에 H급이 298행뿐이라 L·L·M 3대로 구성했습니다.

2. 알람 이력이 없어 무엇을 조치로 정의했는가

팹의 알람 로그와 조치 이력이 짝지어진 공개 데이터는 존재하지 않습니다. 그래서 데이터셋에 라벨로 들어 있는 고장 유형 5종을 알람으로 삼고, 각 유형에 대응하는 조치를 정의했습니다. 임계값은 제가 정한 것이 아니라 데이터셋 문서에 명시된 발생 조건이며, 검증 결과 방열 불량·전력 이상·과부하 세 유형은 실제 라벨과 100% 일치했습니다.

고장 유형판정 조건정의한 조치자동화
블레이드 마모 한계 (TWF)마모 ≥ 200min설비 정지 후 블레이드 교체불가 — 비가역
블레이드 수명 임박 (TWF)마모 ≥ 180min계획 정비 교체 예약 등록가능
스핀들 과전력 (PWF)전력 > 9,000W이송 속도 하향가능
스핀들 저전력 (PWF)전력 < 3,500W절삭 부하 재분배가능
절삭부 방열 불량 (HDF)방열 여유 < 8.6K 이고 회전수 < 1,380rpm냉각수 유량 증대가능
스핀들 과부하 (OSF)마모 × 토크 > 11,000(L) / 12,000(M) minNm이송 속도 하향가능
센서 이상 의심 (RNF·주입)값 고착 / 열역학 위배 / 설비 간 편차 3σ 초과자동조치 차단, 센서 점검 요청차단

자동화 기준은 조치의 가역성입니다. 파라미터를 되돌릴 수 있으면 자동, 설비를 세워야 하면 사람이 판단합니다. 이 기준을 일관되게 적용하면 자동조치가 불가능한 것은 블레이드 교체(비가역)와 센서 이상(값을 믿을 수 없어 어떤 조치도 근거가 없음) 둘뿐입니다. 과전력도 과부하와 같은 스핀들 부하 지표이므로, 설비를 세우기 전에 이송 속도 하향을 먼저 시도합니다.

대신 자동조치에는 재확인이 붙습니다. 조건 해제를 목적으로 하는 조치는 실행 후 다음 샘플링 주기(6분)에 조건이 풀렸는지 확인하고, 풀리지 않았으면 에스컬레이션해 사람을 부릅니다. 사람을 부르는 근거가 "위험해 보여서"가 아니라 "자동으로 해봤는데 안 됐다"가 됩니다.

블레이드 마모만 2단(주의 180min / 경보 200min)인 이유도 가역성입니다 — 교체는 되돌릴 수 없어서 미리 준비 시간이 필요합니다. 실측상 마모 180min 이하에서는 고장이 0건, 200~240min 구간에서 46건이 발생했습니다.

3. 재생 동작

야간 600분을 6분 간격 100스텝으로 재생합니다. 사람 판단이 필요한 긴급 건이 나와도 시계는 멈추지 않습니다 — 실제 야간은 사람이 판단하는 동안에도 흘러가기 때문입니다. 대신 배속이 자동으로 x1로 떨어지고 판단 대기 큐에 쌓이며, 처리하면 원래 배속으로 돌아갑니다.

중요·주의 등급은 자동 처리하고 이력에 기록만 남깁니다. 당직자를 직접 부르는 것은 설비 정지를 수반하거나 자동조치가 실패한 긴급 건으로 한정했습니다. 알람 전량을 사람이 확인하는 대신, 확인해야 할 건수를 줄이는 것이 이 설계의 목적입니다.

긴급 건은 해당 설비를 정지시킵니다. 정지 중 센서값은 물리적으로 결정됩니다 — 구동이 멈추므로 회전수와 부하 토크가 0, 따라서 소비전력도 0(P = T·ω)이 되고, 발열원이 사라진 공정온도는 공기온도 쪽으로 지수 감쇠하며, 가공이 멈췄으므로 블레이드 마모는 그 값에서 누적을 멈춥니다. 공기온도는 팹 환경온도라 설비 정지와 무관하게 계속 측정됩니다. 냉각 시정수만 가정치이고 나머지는 물리로 결정됩니다.

정지하면 가공이 멈추므로 그만큼 야간 생산이 밀립니다. 이것을 정지 손실로 집계합니다 — 판단이 늦을수록 손실이 커지고, "정지 유지"를 선택하면 야간이 끝날 때까지 누적됩니다. 자동조치가 왜 가치 있는지가 이 숫자로 드러납니다.

4. 데이터 분할과 검증

고장이 3.39%로 희소해 층화 추출로 학습 70% : 검증 30%로 나눴습니다(seed=42 고정, 재현 가능). 이 화면의 시계열은 전부 학습에 쓰이지 않은 검증셋 3,000행에서 생성했습니다. 정상군의 ±3σ 관리한계를 알람 임계로 쓰려 했으나, 이 데이터의 고장 조건은 통계적 이상치가 아니라 물리 조건으로 정의돼 있어 3σ가 실제 경보보다 바깥에 놓여 조기경보 역할을 하지 못했습니다(예: 방열 여유 −3σ = 7.1K vs 경보 8.6K). 그래서 3σ는 알람 임계에서 빼고 설비 간 센서 편차 판정에만 사용했습니다.

5. AI가 하는 일과 하지 않는 일

판정과 조치 결정은 AI가 하지 않습니다. 임계 판정, 자동조치 가부, 센서 이상 판정은 전부 결정론적 룰엔진이 처리합니다. LLM은 위의 AI 생성 브리핑과 조치 사유 서술만 담당합니다. 설비 조작을 LLM에 맡기면 환각으로 오조치가 나고, 같은 입력에 다른 출력이 나와 재현이 안 되며, 감사 추적이 불가능하기 때문입니다.

6. 학습 모델은 물리 규칙을 찾아내는가

AI4I는 본래 설명가능 AI(XAI) 연구용 데이터셋입니다. 그래서 판정 룰과 별개로, 학습셋 7,000행에 결정트리를 학습시켜 모델이 물리 규칙을 스스로 복원하는지 확인했습니다. 두 조건을 비교합니다 — 원본 센서 5종만 준 경우와, 물리 파생변수(방열 여유 = 공정온도−공기온도, 전력 = 토크×각속도, 과부하 = 마모×토크)를 함께 준 경우입니다. 성능은 모두 검증셋 3,000행 기준입니다.

7. 가정치

  • 시간축 재구성 — 원본은 로트 단위 독립 스냅샷이라 타임스탬프가 없습니다. 단조 누적되는 유일한 변수인 블레이드 마모를 시간축으로 삼아 정렬 배치했고, 나머지 센서값은 해당 행의 실측값을 평활화 없이 그대로 씁니다.
  • 마모 진행 속도 — 야간 600분 동안 40min 진행한다고 가정했습니다. 제품 1개당 가공 사이클 타임이 원본에 없어 실제 시간 환산이 불가능합니다.
  • 센서 고장 — 원본에 센서 고장 라벨이 없어 값 고착과 편류를 인위적으로 주입했습니다.
  • 설비 구성 — H등급은 검증셋에 298행뿐이라 제외하고 L·L·M 3대로 구성했습니다.
  • 블레이드 교체 — 교체를 승인하면 마모가 0부터 다시 누적됩니다. 새 블레이드이므로 이후 마모 알람은 발생하지 않습니다.
  • 조치 효과 — 조치 후 그래프를 보정하지 않습니다. 조치와 정상 복귀 사이의 인과는 원본이 독립 스냅샷이라 검증할 수 없어, 이력의 "조건 해제"는 데이터상 조건이 풀린 시점만을 뜻합니다.
